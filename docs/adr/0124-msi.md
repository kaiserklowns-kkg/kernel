# ADR-0124: MSI for devices without MSI-X (ABI 18)

- Status: Accepted
- Date: 2026-10-12
- Depends on: ADR-0021 (device capabilities, MSI-X), ADR-0123 (Ethernet
  for real PCs), ADR-0069 (SATA)
- Part of Phase 4 (Hardware) and Phase 10 (Alpha).

## Context

The kernel bound MSI-X only (ADR-0021). Devices with MSI and no MSI-X
were polled:
- the Intel I219 in every recent Intel PC (ADR-0123), every 10 ms;
- Realtek 8168s without MSI-X;
- every AHCI controller (ADR-0069): commands spun, yielding and sleeping
  a millisecond.

Polling costs wake-ups and adds latency, and on a laptop it keeps the
CPU from sleeping. MSI is the older message-signalled interrupt: one
capability (`0x05`) with an address, a data word and, optionally, mask
bits. It needs no table in a BAR. Pin interrupts (INTx) stay out of
scope: they need the I/O APIC's routing from ACPI.

## Decision

- **libs/pci** reads the MSI capability (`Msi`). Whether the address is
  64-bit and whether vectors can be masked decide where the data and mask
  registers are; a capability that does not fit configuration space is
  ignored.
- **The kernel** remembers each function's MSI next to its MSI-X, and logs
  `MSI` for functions that have only that. `DEVICE_IRQ` on a function
  without MSI-X binds its one MSI message:
  - only for `entry` 0;
  - through the same vector allocation and routing as MSI-X;
  - one message (`MME` 0), unmasked, with legacy interrupts off.

  Closing the device turns MSI off before its vector is freed. A function
  with MSI-X always gets MSI-X.
- **ABI 18:** `DEVICE_IRQ` returns which it bound (`interrupt::MSI_X`,
  `interrupt::MSI`). Before, it returned 0 and failed without MSI-X.
  Drivers need to know which, because some devices are programmed
  differently: the 8168's `Config2` bit, the I219's legacy causes.
- **Drivers:**
  - e1000e takes MSI on the PCH LAN, with the legacy interrupt causes.
  - rtl8168 takes MSI where it has no MSI-X, and sets `Config2` to match.
  - ahci binds the controller's interrupt and enables the port's causes.
    A command then waits for the interrupt instead of spinning, with a
    10 ms timer as a fallback, so a lost message costs time, not the
    command.

## Consequences

- The smoke test exercises MSI on every boot: QEMU's ICH9 AHCI has only
  MSI. Both checks are now pinned:
  - the kernel lists it as `MSI`;
  - the SATA disk's reads, writes and flushes go through interrupts
    (`ahci: ... 32 command slots, MSI`).
- The I219 and 8168 paths use it too. As in ADR-0123, they are not tested
  on hardware yet.
- Still out of scope:
  - several MSI messages per function (one is enough for these drivers);
  - pin interrupts;
  - interrupts for the HD Audio driver, which still polls its position.
