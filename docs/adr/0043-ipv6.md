# ADR-0043: IPv6

- Status: Accepted
- Date: 2026-10-04
- Depends on: ADR-0023 (network stack, sockets), ADR-0024 (TCP, DNS),
  ADR-0026 (entropy), ADR-0028 (HTTP), ADR-0031 (TLS)

## Context

The master spec requires IPv6 alongside IPv4. Until now the stack spoke
only IPv4: Ethernet, ARP, IPv4, ICMP, UDP, TCP and DHCP (ADR-0023,
ADR-0024), with a socket protocol whose messages carry 4-byte addresses.

IPv6 is not "IPv4 with longer addresses". A host needs:

- ICMPv6 for errors and echo;
- Neighbor Discovery (ND) instead of ARP, with a neighbor cache that
  tracks reachability;
- duplicate address detection (DAD) for every address it uses;
- stateless autoconfiguration (SLAAC) from router advertisements;
- multicast reception for the groups ND relies on;
- extension headers it must parse or reject correctly.

Everything that names addresses must also take IPv6 ones: the socket
protocol, DNS (AAAA records), and the utilities a user types addresses
into.

QEMU's user network (slirp), which every test boot uses, has IPv6 on by
default:

- it answers router solicitations from `fe80::2`, advertising
  `fec0::/64` (on-link, autonomous);
- it advertises its DNS proxy `fec0::3` (RDNSS) only when the host
  itself has an IPv6 DNS server, which the Windows test machine does
  not;
- it answers ND for `fec0::2`/`fe80::2` and echo requests to them;
- it connects TCP and UDP for `fec0::2` to the host's `::1`, the way it
  maps 10.0.2.2 to 127.0.0.1;
- it does not forward ICMPv6 echo to other addresses.

The smoke test confirms all of this. One trap: `-netdev user,ipv6=on`
alone turns IPv4 off (QEMU enables only the families named once one is
named), so xtask names both.

## Decision

### Addresses: `oceans-inet` (new crate)

`Ipv4`, `Ipv6`, `IpAddr` (either family), strict text parsing (RFC 4291,
no zone indices), RFC 5952 formatting (`Colons`), IPv4-mapped conversion
and `split_host_port` (`[fec0::2]:53`). It has no allocation and no I/O,
so the stack, the socket protocol, the HTTP URL parser and every utility
share one implementation.

### The stack (`oceans-net`, new module `ipv6`)

- **Off until enabled.** `Stack::enable_ipv6(key, now)` starts IPv6. The
  `net` service enables it when a device is present. IPv4-only users of
  the library see no change.
- **Packets (RFC 8200):**
  - the header is length-checked;
  - hop-by-hop options (first only), destination options and routing
    headers are processed, with option actions by type bits;
  - a routing header with segments left draws a Parameter Problem: we
    are not a router;
  - fragments are not reassembled: only atomic fragments (RFC 6946)
    pass;
  - an unknown next header draws Parameter Problem code 1.
- **ICMPv6 (RFC 4443):**
  - echo is answered (to our addresses and to all-nodes);
  - echo replies go to ping sockets;
  - port unreachable is sent for closed UDP ports;
  - Packet Too Big records a path MTU (10 minutes, RFC 8201) and shrinks
    TCP segments to that destination.
  - Errors are never sent about errors, `::` or multicast sources, or
    (except option problems) multicast destinations, and are
    rate-limited: a bucket of 10, refilled at 10 per second.
- **Neighbor Discovery (RFC 4861):**
  - **Validation:** hop limit 255, code 0, length, and every option's
    nonzero length; NS from `::` only to a solicited-node group, without
    a link-layer option; solicited NA never to multicast.
  - **Neighbor cache:** INCOMPLETE, REACHABLE, STALE, DELAY and PROBE.
    - Timers: ReachableTime randomised over [0.5, 1.5) × base, 1 s
      retransmissions, a 5 s DELAY, then 3 multicast or unicast probes.
    - Advertised timers are clamped (100 ms to 1 h), so a hostile router
      can make us neither spin nor stop probing.
    - At most 32 entries; the least recently used non-INCOMPLETE entry is
      evicted.
    - Packets wait for resolution: 4 per neighbor, 32 in all; when
      resolution fails they are dropped and counted.
  - **Override rules:** STALE on new or changed link-layer addresses;
    REACHABLE on solicited NA; a non-override NA with a different address
    only demotes REACHABLE; a router whose NA clears the R flag leaves
    the default router list.
  - **Routers:** up to 4 default routers (one believed reachable is
    preferred), on-link prefixes, hop limit, MTU (1280–1500), RDNSS
    (RFC 8106), each with its lifetime.
  - **Router solicitation:** once the link-local address is usable;
    three tries, 4 s apart.
  - **Not done:** Redirect messages are ignored (allowed for hosts; we
    always use the default router).
- **Addresses (RFC 4862):**
  - A link-local address at start, and one per autonomous /64 prefix.
  - Every address is tentative until DAD: one NS from `::`, after a
    random delay of up to 1 s for the first. A conflicting NA, or another
    node's NS from `::` for the same address, marks it duplicate.
  - Lifetimes: preferred, then deprecated (not chosen for new traffic),
    then removed, with RFC 4862's two-hour rule against advertisements
    that cut a valid lifetime.
  - Source selection follows RFC 6724, reduced to one interface:
    link-local for link-scoped destinations; otherwise preferred before
    deprecated, then the longest matching prefix.
- **Interface identifiers: RFC 7217, not EUI-64.**
  - Identifier = SipHash-2-4(prefix, MAC, DAD counter) under a 128-bit
    key, avoiding reserved identifiers (RFC 5453).
  - On a duplicate, a new address is generated with the next DAD
    counter, up to 3 times (RFC 7217 §6); then the address stays marked
    duplicate and unused.
  - The `net` service draws the key from kernel randomness (ADR-0026) at
    every boot. An address is stable while the system runs, and the
    machine is not identifiable from its address across networks or
    boots (RFC 8064 recommends against EUI-64 for this reason).
- **MLDv2 (RFC 3810), host side.** We join the solicited-node group of
  each address before probing it: an unsolicited report sent twice
  (state change), current-state reports in answer to queries (after a
  random part of the maximum response delay), and leave records when an
  address goes. Switches that snoop MLD then still deliver ND to us.
- **Multicast filter.** The stack accepts frames to `33:33:00:00:00:01`
  and to `33:33:ff:xx:xx:xx` for its own solicited-node groups (tentative
  addresses included). It drops frames with its own source MAC, so a
  link that loops frames back cannot fail DAD against ourselves.
- **UDP and TCP over either family.**
  - Sockets are dual-stack: a UDP or TCP port serves both families;
    `Datagram::from` and the TCP endpoints are `IpAddr`.
  - Pseudo-header checksums: RFC 8200 §8.1 for IPv6, with the UDP
    checksum mandatory (zero is dropped).
  - TCP announces MSS 1440 over IPv6 (link MTU − 60).
  - TCP connections remember their local IPv6 address and match it on
    input.
  - ISNs hash the full IPv6 address.
- **Bounds.** 8 addresses, 4 routers, 8 prefixes, 32 neighbors, 16 path
  MTUs.

### Netdev and drivers

The stack needs the driver to deliver its multicast frames:

- **virtio-net:** without `VIRTIO_NET_F_CTRL_RX` the device is
  promiscuous; QEMU resets virtio-net to promiscuous. Nothing changes.
- **Other drivers** (e.g. the Intel Ethernet one) must accept all
  multicast, or at least `33:33:00:00:00:01` and `33:33:ff:*`. The netdev
  protocol has no filter operation yet, so "all multicast" is the
  contract. The stack filters by itself.

### Socket protocol (`oceans-net-proto`), compatible

The existing operations keep their exact formats. New ones carry 16-byte
addresses, with IPv4 as IPv4-mapped (`::ffff:a.b.c.d`):

| op | name | data → reply |
|---|---|---|
| 16 | `SEND_TO6` | `[address 16][port u16][payload ≤ 236]` |
| 17 | `RECV6` | → `[address 16][port u16][flags u8][payload ≤ 236]` |
| 18 | `TCP_CONNECT6` | `[address 16][port u16][bits u64]` + notification |
| 19 | `INFO6` | → `[flags][hop limit][mtu u16][count]`, addresses `[16][prefix][state][link-local]`, `[router 16][dns 16]` |

- The old `RECV` skips datagrams from IPv6 senders, which it cannot name.
- Clients:
  - `Socket::send_to_ip` and `Socket::recv_ip`;
  - `TcpStream::connect_ip` and `connect_ip_on`;
  - `info6` and `NetInfo6`.
- **Name resolution:**
  - `reach` gives the families usable and the DNS server: DHCP's first,
    else the RA's RDNSS, reached over either family.
  - `lookup` / `lookup_via` ask A and AAAA; one failing query does not
    hide what the other found.
  - `resolve_ip` returns one address: IPv6 first if the stack has a
    global IPv6 address, else IPv4 (RFC 6724 §6, reduced).
  - `resolve` and `resolve_via` stay IPv4-only.
- **`connect_host`** races a name's addresses, as RFC 8305 (Happy
  Eyeballs) describes: the preferred family first, the other after
  250 ms or as soon as the first fails; the first connection up wins.
  An IPv6 address without working IPv6 beyond it (common behind QEMU on
  an IPv4-only host) then costs 250 ms, not a failure.

### DNS (`oceans-dns`)

- `build_query_for::<R>` and `parse_response_for::<R>`, generic over
  `Record` (A: `Ipv4`, AAAA: `Ipv6`); `Answer<A>` is generic.
- The A-only functions are unchanged.
- The record type and its exact data length are checked.
- `respond_with` answers A and AAAA for test servers.

### Utilities

- **`ifconfig`:** `inet6 ADDRESS/64 link-local|autoconf [tentative|
  deprecated|duplicate]`, and `inet6 router … dns …`.
- **`ping HOST`:** an IPv4 or IPv6 address (`fec0::2`, `[fec0::2]`) or a
  name.
- **`host`:** prints `has address` (A) and `has IPv6 address` (AAAA). Its
  server may be `[v6]:port`.
- **`nc` and `fetch`:** take `[v6]` literals (`http://[fec0::2]:8080/`;
  `oceans-http` keeps the brackets for `Host:` and redirects, and
  `Url::hostname` drops them for connecting and TLS names). They connect
  with `connect_host`.
- **`net-echo`:** echoes over IPv6 too.
- **`net` log lines:** `net: IPv6 ADDRESS/64 (link-local|SLAAC)`,
  `net: IPv6 router … dns …`, and a line for duplicates.

## Consequences

- The system works on IPv6-only and dual-stack links. Under QEMU it gets
  `fe80::…` and `fec0::…/64` at boot, and reaches the host over IPv6.
- Programs written for the IPv4 operations keep working. New programs
  use the `_ip` calls and get both families.
- **Addresses change from boot to boot.** RFC 7217 wants them stable
  across reboots on the same network. That needs a persistent secret,
  and the `net` service has (by least privilege) no storage. A later
  ADR can hand it one, e.g. a key file read by init.
- **No reassembly** of IPv6 fragments, and no fragmentation when sending.
  UDP datagrams are limited to what the link MTU carries; TCP follows the
  path MTU.
- **Not implemented:**
  - temporary addresses (RFC 8981);
  - DHCPv6;
  - the Redirect function;
  - a destination cache beyond path MTU;
  - IPv6 hostfwd in the smoke test: the guest's address is random per
    boot, and slirp needs it in advance.

## Alternatives considered

- **EUI-64 interface identifiers:** deterministic and simplest, but they
  embed the MAC and track the machine across networks; RFC 8064 advises
  against them. RFC 7217 costs one SipHash.
- **A persistent RFC 7217 key:** stable addresses across boots, but it
  needs a storage capability for `net`. Deferred, see Consequences.
- **One socket API with 16-byte addresses only** (replacing the IPv4
  operations): simpler wire format, but every existing client would
  change at once. Versioned operations keep IPv4 programs as they are.
- **Separate IPv4 and IPv6 sockets:** BSD's choice. Dual-stack sockets
  give servers (`net-echo`, TCP listeners) both families with no code.
- **IPv4-mapped addresses inside the stack:** one address type
  everywhere, but every IPv4 path would carry and check 16 bytes. `IpAddr`
  keeps IPv4 code as it was.
- **Reassembling fragments:** needed only for oversized UDP (DNS over UDP
  stays small, TCP uses MSS). A bounded reassembly buffer is a known
  denial-of-service surface; left out until something needs it.
- **Asking the driver to filter multicast:** a netdev operation for it
  would let NICs drop unrelated multicast in hardware. Every driver must
  then implement it; "all multicast" works today, and the stack filters.

## Checklist (master spec §48)

- **Purpose:** IPv6 alongside IPv4, from link to applications.
- **Architecture:**
  - `oceans-inet` for addresses;
  - `oceans-net`'s `ipv6` module (ND, SLAAC, MLD, ICMPv6, packets) under
    the existing UDP and TCP, which now take either family;
  - `siphash` for RFC 7217 identifiers;
  - versioned socket operations in `oceans-net-proto`;
  - AAAA in `oceans-dns`; IPv6 literals in `oceans-http`.
- **API:**
  - library: `Stack::enable_ipv6`, `ipv6_config`, `neighbor_state`;
    `send_to` and `tcp_connect` take `impl Into<IpAddr>`;
  - protocol: ops 16–19;
  - client: `Socket::{send_to_ip, recv_ip}`, `TcpStream::{connect_ip,
    connect_ip_on}`, `info6`, `reach`, `lookup`, `lookup_via`,
    `resolve_ip`, `connect_host`;
  - DNS: `build_query_for`, `parse_response_for`, `respond_with`;
  - HTTP: `Url::hostname`.
- **Dependencies:** none outside the repository; SipHash is implemented
  and checked against its reference vectors.
- **Security:**
  - all input is untrusted: every header, option and length is checked
    before use;
  - ND needs hop limit 255, so it cannot come from off the link;
  - router parameters are clamped, tables and queues bounded, errors
    rate-limited;
  - `RECV` never misreports an IPv6 sender as IPv4;
  - addresses do not reveal the MAC, and change per boot;
  - DNS answers must match the query's id, name and record type.
  - SEND (RFC 3971) is not implemented: on-link attackers can spoof ND,
    as with ARP.
- **Testing:**
  - host tests in `oceans-inet`: parsing, RFC 5952 formatting with every
    zero-run pattern round-tripping, prefixes, host:port splitting;
  - `oceans-dns`: AAAA queries and answers, wrong-type and wrong-length
    records, mutation fuzzing;
  - `oceans-http`: bracketed hosts, `Host:` headers;
  - `oceans-net`:
    - SipHash vectors;
    - link-local bring-up (MLD report, DAD probe, RS with retries,
      stable and keyed identifiers);
    - IPv6 off by default; DHCP and its backoff unchanged with it on;
    - SLAAC from a slirp-like RA (router, RDNSS, MTU, router learned
      STALE);
    - invalid RAs (source, hop limit, options, checksum, prefixes);
    - lifetimes and the two-hour rule;
    - DAD conflicts by NA and by NS, regeneration, then duplicate;
    - NS answering and validation, multicast MAC filtering, loopback
      drop;
    - address resolution, echo both ways, off-link through the router,
      no route;
    - the full NUD cycle and giving up on unanswered resolution, with
      queue bounds;
    - echo to unicast and all-nodes;
    - UDP over IPv6 (mandatory checksum, port unreachable, size);
    - ICMP error rate limit;
    - extension headers (each rule above);
    - MLD queries;
    - mutation fuzzing of RA/NS/NA/extension-header frames;
    - TCP over IPv6 between two stacks, with 1500-byte packets, Packet
      Too Big shrinking segments, and a clean close;
    - refused connections;
    - source address selection.
  - **Smoke** (QEMU user network, `ipv4=on,ipv6=on`), all checked on
    the console:
    - the `net` log shows the link-local and SLAAC addresses and the
      router from the RA (and its DNS, where QEMU advertises one);
    - `ifconfig` shows both addresses and the router;
    - `ping` gets replies from `fec0::2` and `fe80::2`;
    - `host` gets an AAAA answer over UDP/IPv6 from a DNS server on the
      host's `[::1]`;
    - `nc` exchanges a line over TCP/IPv6 with a host server on `[::1]`;
    - `fetch` downloads `http://[fec0::2]:PORT/ipv6.txt` from an HTTP
      server on `[::1]`;
    - the IPv4 `host` test also checks the AAAA line.
- **Failure behaviour:**
  - a duplicate address is never used: it is regenerated up to 3 times,
    then reported;
  - unresolvable neighbors drop their queued packets after 3 probes
    (counted);
  - routers, prefixes, addresses and DNS servers vanish when their
    lifetimes end;
  - without a router only the link is reachable (`NoRoute`);
  - without randomness IPv6 stays off (logged) and IPv4 is unaffected;
  - `connect_host` falls back to the other family when one fails.
