# ADR-0069: AHCI (SATA)

- Status: Accepted
- Date: 2026-10-05
- Depends on: ADR-0021 (PCI and userspace drivers), ADR-0022 (the
  filesystem on disk), ADR-0035 (mounts), ADR-0040 (NVMe), ADR-0068
  (hardware validation)

## Context

ADR-0068 published the Tier 1 list and named the drivers that keep common
PCs out of it. The largest storage gap is SATA: many desktops and laptops
still have a SATA disk or SSD, often as their only disk, and their
firmware runs SATA through an AHCI controller.

AHCI (Serial ATA AHCI 1.3.1) is a public, stable standard. Every
controller speaks the same register interface, and the disks behind it
speak the ATA command set (ACS), so one driver covers the class. The PCI
class is 01 (mass storage), subclass 06 (SATA), interface 01 (AHCI).

QEMU's q35 machine has an AHCI controller built in (ICH9, `8086:2922` at
`00:1f.2`), so the driver can be tested in CI.

## Decision

- **A userspace driver, `ahci`**, built like `nvme` (ADR-0040).
  - **Authority:**
    - one device capability, taken by class (`grant =
      device-class:010601`, the first AHCI controller);
    - the endpoint it serves (`provide = sata`);
    - a log.
  - **Protocol:** it serves the block protocol unchanged (sessions, shared
    buffers, `INFO`, `READ`, `WRITE`, `FLUSH`), so the fs service and
    `disk` work on it as they are.
- **The controller:**
  - Its registers are BAR 5 (the `ABAR`).
  - If the controller supports the BIOS/OS handoff, the driver takes
    ownership first (waiting up to 2 s; if the firmware does not let go,
    it says so and proceeds).
  - AHCI mode is enabled (`GHC.AE`) and controller interrupts are off.
  - The controller is not reset as a whole: each port is stopped and set
    up on its own.
- **The disk:**
  - The ports implemented (`PI`) are looked at in order. A port whose link
    is up (`PxSSTS.DET = 3`, `IPM = 1`) and whose device has the SATA disk
    signature (`PxSIG = 0x00000101`) is set up.
  - **The first such disk is served**, like `nvme`'s one namespace.
  - Ports holding something else (ATAPI drives, port multipliers) are
    logged and skipped, and so are disks the driver refuses (below); the
    next port is then tried.
  - Controllers with staggered spin-up get every port spun up first.
- **A port:**
  - The command engine is stopped safely: `PxCMD.ST` cleared and `CR`
    waited for, then `FRE` and `FR` (500 ms each).
  - One page of DMA memory holds the command list (1 KiB aligned), the
    received-FIS area (256-byte aligned) and one command table (128-byte
    aligned) with its PRD table.
  - Port interrupts are off and errors cleared. FIS receive is enabled;
    once the disk is not busy (up to 10 s, for a spinning disk), the
    command engine starts. A disk that stays busy gets a COMRESET.
  - Controllers without 64-bit addressing (`CAP.S64A`) are refused if the
    DMA memory lies above 4 GiB.
- **`IDENTIFY DEVICE`** gives:
  - the model, serial and firmware (for the log);
  - 48-bit addressing and the sector count (words 100–103);
  - the logical and physical sector sizes (words 106, 117–118);
  - the write cache (supported and enabled) and `FLUSH CACHE EXT`.

  Refused, with a log line:
  - disks without 48-bit addressing (none made since about 2003);
  - logical sectors other than 512 bytes, the protocol's sector size
    (4 KiB-native SATA disks are rare; 512e disks are served).
- **Data path:**
  - `READ DMA EXT`, `WRITE DMA EXT`, `FLUSH CACHE EXT` (`FLUSH CACHE` on
    disks without it).
  - One command in flight, in slot 0, as in `nvme`.
  - Each command moves data between the disk and a 128 KiB bounce buffer
    of contiguous DMA memory, described by PRD entries of at most 4 MiB.
  - A request is split into commands of at most 256 sectors (the bounce
    buffer).
  - Clients copy through their session buffers: no client sees a physical
    address.
- **Durability:** with the write cache on, the block protocol's `FLUSH`
  sends a cache flush; without it, completed writes are durable. When the
  service stops, the cache is flushed and the port stopped.
- **Completion is polled:**
  - The kernel delivers only MSI-X (ADR-0021); AHCI controllers have MSI
    or pin interrupts (QEMU's ICH9 has MSI only).
  - The driver watches `PxCI` and `PxIS`, yielding between looks and
    sleeping 1 ms every 64.
- **Failures:**
  - A device or port error (`PxIS.TFES`, `HBFS`, `HBDS`, `IFS`, or the
    error bit in `PxTFD`) is logged with its meaning. The command engine
    is restarted (or the link reset, if the disk stays busy).
  - The error maps to a block status: sector not found (`IDNF`) → out of
    range; anything else → I/O error.
  - A command not completed within 30 s resets the link (COMRESET through
    `PxSCTL`) and restarts the port.
  - A port that cannot be brought back answers `IoError`, logged.
  - Device-reported values are bounds-checked: register offsets against
    the `ABAR`, the sector count against 2^48, identify strings shown only
    if printable.
- **No disk:** without a SATA disk (a controller with empty ports), or
  with a controller it cannot use (its `ABAR` cannot be mapped), the
  driver logs it once and keeps running, answering every request with
  `IoError`, as `usb-storage` does without a stick. Exiting would make
  init restart it five times for nothing. Without an AHCI controller, init
  cannot open the device and does not start the service (as for `nvme`).
- **Never writing on its own:** the driver writes only on a client's
  `WRITE`. Whether a disk is formatted stays the fs service's decision: it
  formats only a disk whose start is blank (ADR-0022).
- **`libs/ahci` (`oceans-ahci`)** holds everything that is plain data, so
  it is tested on the host:
  - registers, bits and signatures;
  - `CAP`, `SStatus` and task-file decoding;
  - the page layout;
  - FIS, command header and PRD encoding;
  - `IDENTIFY DEVICE` parsing;
  - transfer splitting.
- **In the system:**
  - **Service:** `sata` (image `ahci`) after `nvme`.
  - **Filesystem:** `satafs` (`use = sata as block`), another fs instance,
    which the system filesystem shows as `/sata` (`use = satafs as
    mount:sata`).
  - **Shell:** the shell may use `sata` (`run disk out use:sata -- info`).
  - **The hardware profile** (ADR-0068) keeps `/sata`: on a real machine
    the root stays on NVMe and the SATA disk appears at `/sata`.
  - **init:** room for 24 endpoints (from 16) and 28 grants per service
    (from 24), since `sata` and `satafs` filled both tables.
- **Tests in QEMU:**
  - **Regular smoke:** q35's AHCI controller holds the boot disk (the ESP,
    attached without `if=`). The driver identifies it, and `satafs` leaves
    it untouched (it is not blank), which is what a real machine's
    Windows or Linux SATA disk must see.
  - **Hardware smoke:** a blank 16 MiB SATA disk on port 0 (`-device
    ide-hd,bus=ide.0`) is formatted, a file written to `/sata` in boot 1
    is read back in boot 2, and `sysreport` shows the controller driven.

## Consequences

- Oceans reads and writes SATA disks on AHCI controllers, the other
  storage of current PCs. SATA joins the Tier 1 list's storage line.
- **Not done yet:**
  - **Native command queuing and several commands in flight:** one
    command is enough for one filesystem, as for NVMe; speed needs
    measurements on real hardware first (§51).
  - **Interrupts:** polling costs some CPU while a command runs. MSI
    support in the kernel would let the driver sleep instead.
  - **Several disks:** only the first disk is served. A second disk needs
    a second endpoint, which the block protocol and init can already
    express; it waits for a machine that needs it.
  - **Hot plug, port multipliers, ATAPI drives, TRIM, 4 KiB-native
    disks:** not needed by the filesystem today.
  - **Controllers in RAID mode** (class 01.04, the Intel RST default on
    some laptops) are not AHCI and are not driven: the firmware setting
    must be AHCI.
  - **Small `ABAR`s:** the kernel maps BARs of at least a page (ADR-0021),
    and some Intel chipsets have a 2 KiB `ABAR`. On those the driver
    cannot map its registers, says so and answers `IoError`; the kernel
    then needs to map a sub-page BAR whose page holds nothing else. To be
    checked on the first real machine.

## Alternatives considered

- **AHCI inside the kernel:** against ADR-0002 and ADR-0021; the driver
  needs nothing a userspace service cannot have through its device
  capability.
- **MSI in the kernel first:** the larger change, and polling with one
  command in flight is cheap enough to start with.
- **Exiting when no disk is attached:** init would restart the driver up
  to five times and then give up; keeping it running and answering
  `IoError` is quieter and lets a client ask at any time.
- **Serving every disk at once:** needs one endpoint per disk; one disk
  covers the machines in sight.
- **Serving 4 KiB logical sectors through whole blocks, as `nvme` does:**
  such SATA disks are rare; refusing them clearly keeps the driver small.

## Checklist (master spec §48)

- **Purpose:** SATA storage through AHCI controllers, a Tier 1 storage
  class.
- **Architecture:**
  - the `ahci` service (user/ahci) serves the block protocol as `sata`;
  - `oceans-ahci` (libs/ahci) holds the data structures;
  - `satafs` is an fs instance mounted at `/sata`.
- **API:**
  - the block protocol (unchanged);
  - the endpoint `sata`;
  - grant `device-class:010601`.
- **Dependencies:** none new (the Serial ATA AHCI 1.3.1 and ATA/ATAPI
  Command Set specifications).
- **Security:**
  - the driver holds one device capability, its endpoint and a log;
  - clients never see physical addresses;
  - device-reported values are bounds-checked;
  - it never writes except for a client's `WRITE`, and the fs formats only
    blank disks;
  - the driver is isolated: a crash restarts it without affecting the
    kernel.
- **Testing:**
  - **Host unit tests (`oceans-ahci`):**
    - `CAP`, version, `PI`, `SStatus` and task-file decoding;
    - the layout's alignments;
    - FIS, command header and PRD encoding, with an exhaustive check that
      PRD entries cover a buffer exactly;
    - `IDENTIFY DEVICE` parsing: LBA48 and 28-bit counts, sector sizes
      (512, 512e, 4Kn), write cache, invalid words, non-ASCII strings;
    - transfer splitting.
  - **`libs/hardware`:** the matrix row and the published line.
  - **Smoke (QEMU, release, debug and `-cpu max`):** the ESP on AHCI is
    identified and left untouched.
  - **Hardware smoke:** a blank SATA disk is formatted, written and read
    back after a reboot; `sysreport` shows the controller driven.
- **Failure behaviour:**
  - errors are logged and mapped to block statuses;
  - device errors restart the command engine; timeouts reset the link;
  - a port that cannot be brought back fails every request;
  - unsupported disks are refused at start with a log line;
  - without a disk, every request fails with `IoError`, and the driver
    does not restart in a loop.
