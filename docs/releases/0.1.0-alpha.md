# Oceans 0.1.0 alpha: release notes (draft)

**Not yet released.** This page is a draft. A release needs:

- its own signing key (see "Before publishing");
- the checks below on real machines.

## What it is

The first Oceans you can boot on a PC from a USB stick. It is for
developers and testers. Expect crashes; do not keep anything you cannot
lose on it.

## What is in it

**Machine and drivers.** A Rust microkernel (ABI 15), on Tier 1 hardware
([compatibility](../hardware/compatibility.md)):
- storage: NVMe and SATA (AHCI);
- input and USB: xHCI USB keyboards and mice, USB sticks;
- network: Intel 82574L / e1000e;
- display: the UEFI framebuffer.

**Userspace.**
- init with service supervision and a shell;
- crash-consistent root filesystem; FAT on removable media;
- IPv4/IPv6, TCP, DNS, TLS.

**Apps.**
- Oceans Core runs signed apps, with declared permissions and consent
  prompts.
- Apps can be native (Rust), Go (wasm) or web (SvelteKit + Bun).
- The Store installs them, with confirmation in a system dialog.

**AI.** An agent runtime with approval-gated tools and an OpenAI-compatible
model gateway.

**Desktop.** A desktop with app windows, a launcher, a Terminal and
notifications. The web experience (Control Center, Apps, AI Center,
Settings) is served by the bridge.

**Developers.** The SDK and the `oceans` tool: templates, keys, builds and
a local Store ([sdk](../../sdk/README.md)).

**Alpha tools.**
- `sysreport`: a hardware report (ADR-0068).
- `diag`: the kept log and crash reports (ADR-0070).
- `update`: signed system updates into a second slot, with the previous
  release kept in the boot menu (ADR-0071).

## Installing

```bash
cargo xtask usb
```

Write `build/oceans-usb.img` to a USB stick (Rufus, balenaEtcher or `dd`).
Then boot a UEFI machine from it, with Secure Boot off. A blank NVMe SSD
becomes the root filesystem. Only a blank disk is formatted: a disk that
holds data is left alone.

## Known limits

- **Secure Boot is not supported.** Oceans does not do suspend, Wi-Fi,
  audio, GPU acceleration or a hardware boot counter (going back to the
  previous release is chosen in the boot menu).
- **The developer key:** apps and updates are signed with the development
  key. Its private half is in the repository (see below).
- **Logs:** they are kept only while the system runs (64 KiB).

## Before publishing

1. **A release key.**
   - The development key's seed is public (`tools/keys`). Anyone can sign
     with it.
   - A published image must trust a release key instead, for apps
     (`trust.keys`) and for updates (`update.keys`), with the private half
     kept off the repository.
   - Until then, an image is for development only.
2. **Real machines:** at least one Tier 1 machine passes the validation in
   [compatibility.md](../hardware/compatibility.md#validating-a-machine).
3. **The release itself:**
   - a tag `v0.1.0-alpha`;
   - the USB image and its SHA-256 attached to a GitHub release;
   - CI green on the tagged commit.
