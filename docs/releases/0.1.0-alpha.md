# Oceans 0.1.0 alpha: release notes (draft)

**Not yet released.** This page is a draft. A release needs:

- a build with the release key (see "Before publishing");
- the checks below on real machines.

## What it is

The first Oceans you can boot on a PC from a USB stick. It is for
developers and testers. Expect crashes; do not keep anything you cannot
lose on it.

## What is in it

**Machine and drivers.** A Rust microkernel (ABI 15), on Tier 1 hardware
([compatibility](../hardware/compatibility.md)):
- storage: NVMe and SATA (AHCI);
- input and USB: xHCI USB keyboards and mice, USB sticks;
- network: Intel 82574L / e1000e;
- display: the UEFI framebuffer.

**Userspace.**
- init with service supervision and a shell;
- crash-consistent root filesystem; FAT on removable media;
- IPv4/IPv6, TCP, DNS, TLS.

**Apps.**
- Oceans Core runs signed apps, with declared permissions and consent
  prompts.
- Apps can be native (Rust), Go (wasm) or web (SvelteKit + Bun).
- The Store installs them, with confirmation in a system dialog.

**AI.** An agent runtime with approval-gated tools and an OpenAI-compatible
model gateway.

**Desktop.** A light desktop with a menu bar, a dock, a panel of apps,
windows that move and minimize, a Terminal and notifications, with
interface text in Noto Sans and Thai (ADR-0076..0078). The web
experience (Control Center, Apps, AI Center, Settings) is served by the
bridge, for use from another device.

**Developers.** The SDK and the `oceans` tool: templates, keys, builds and
a local Store ([sdk](../../sdk/README.md)).

**Alpha tools.**
- `sysreport`: a hardware report (ADR-0068).
- `diag`: the kept log and crash reports, including the previous boot's
  (ADR-0070, ADR-0074).
- `update`: signed system updates into a second slot, with the previous
  release kept in the boot menu (ADR-0071).

## Installing

Download the release's files into one folder and check them against the
release key, which is in this repository (`tools/keys/oceans-release.pub`)
and not taken from the download (ADR-0075):

```bash
cargo run -p oceans-dev -- verify DOWNLOADS --key 5fcfd97af4fd47b1406b085bd52f0f3da385977b6601c4473efc55c2992f87f0
```

Then write `oceans-0.1.0-alpha-usb.img` to a USB stick (Rufus, balenaEtcher
or `dd`).
Then boot a UEFI machine from it, with Secure Boot off. A blank NVMe SSD
becomes the root filesystem. Only a blank disk is formatted: a disk that
holds data is left alone.

## Known limits

- **Secure Boot is not supported.** Oceans does not do suspend, Wi-Fi,
  audio, GPU acceleration or a hardware boot counter (going back to the
  previous release is chosen in the boot menu).
- **One release key:** it signs both the system and its first-party
  apps. It cannot be rotated or revoked yet.
- **Logs:** the current and the previous boot only (ADR-0074).

## Before publishing

1. **The release key** (ADR-0072, ADR-0075, [tools/keys](../../tools/keys/README.md)):
   - made by the publisher with `oceans keygen`, kept outside the
     repository, with an offline backup. Its public half is published in
     `tools/keys/oceans-release.pub`.
   - Then, from the commit to tag:
     `OCEANS_RELEASE_KEY=PATH cargo xtask release`. It writes
     `build/release`: the image, the update `.opk`, `release.keys`,
     `BUILD-INFO`, `SHA256SUMS` and `SHA256SUMS.sig`. It refuses a key
     other than the published one.
   - Images from `cargo xtask usb` trust the public development key: they
     are for development only.
2. **Real machines:** at least one Tier 1 machine boots the release image
   (`build/release/oceans-0.1.0-alpha-usb.img`) and passes the validation
   in [compatibility.md](../hardware/compatibility.md#validating-a-machine).
3. **The release itself:**
   - a tag `v0.1.0-alpha`;
   - the files of `build/release` attached to a GitHub release;
   - CI green on the tagged commit.
